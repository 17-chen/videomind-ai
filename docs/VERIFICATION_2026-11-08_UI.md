# 2026-11-08 登录、时间与任务终态界面修复

## 问题与实际证据

用户截图显示登录提交后停留、时间 hydration 错误（同一时刻服务器 07:12/浏览器 15:12），以及任务阶段 completed 时仍显示处理中。只读聚合核查实际云端 Video=completed、Task=succeeded/completed，成功任务从 started_at 到 finished_at 约 111 秒；这不是单独 ASR 耗时或吞吐基准。未读取正文、账号资料、密钥或浏览器 Cookie。

前端容器可访问 Supabase 公共 JWKS（200，单次约 1.3 秒），匿名 dashboard 重定向保持相对 /auth；没有证据说明是服务商持续断连或跳错端口。旧登录成功使用 push 后立即 refresh，新实现以 SDK 完成持久化会话后完整文档 replace 进入 dashboard，规避旧导航/预取状态；不把缓存推断写成唯一已证明根因，不放宽服务端会话验证。无会话或认证失败不会跳入。

## 修复

- 统一日期格式化为显式 Asia/Shanghai；无 offset 的 API 时间按后端 UTC 处理，无效值走原占位文案。不靠屏蔽 hydration 警告解决。
- 视频操作通过现有本人权限接口同时获取最新 Video/Task，显示状态及按钮使用新快照；每次请求结束后再间隔 3 秒，无重叠 setInterval；终态停止轮询并刷新完整详情，卸载后忽略返回结果。队列通知终态后隐藏，操作错误仍可见。补齐 completed 的中英文阶段名。
- 成功登录完整文档导航；显式拒绝 SDK 未建立 session 的异常结果。仍需 Supabase 服务端验证，不使用本地状态放行受保护 API。
- CI 扩展为执行 scripts/*.test.mjs，将这三项回归纳入检查。未引入新依赖。
