| 要了解什么 | 文档 | 用途 |

## 按需查阅

- [TODO](../TODO.md)：具体待办。它是任务清单，完成状态须与代码和验收结果核对。
- [CHANGELOG](../CHANGELOG.md)：按日期记录有意义的变化。
- [DECISION_LOG](../DECISION_LOG.md)：已经接受的长期技术决策。
- [API 文档](api.md)：接口说明；实际接口以运行中的 `/docs` 或源码 `backend/app/api/v1/routes/` 为准。该文档含早期阶段描述，需在下一轮 API 文档修订中同步。
- [项目书](project-plan.md)：早期产品目标和初始方案，用来理解项目意图；其中 Whisper 自动回退、`create_all` 等内容不是当前已验收能力。
- [部署审计](deployment-audit.md)：2026-08-01 的历史快照；版本号和生产化状态已有变化。
- [早期自查](self-review.md)：Phase 2–6 期间的历史记录；不要用它判断今天的运行状态。
- [README](../README.md)：安装和启动入口；涉及阶段或版本时优先核对本页和项目上下文。

## 状态用语

- **代码已实现**：能在仓库定位到实现，尚不保证目标环境已配置或端到端通过。
- **此前验证通过**：仓库记录了过去的测试、构建或运行结果，需在新环境复验。
- **当前验证通过**：在 2026-10-08 自查中实际观察到的结果。
- **待验收**：缺少真实样例、配置、服务或测试证据。

## 每次恢复项目时

1. 读 [项目交接](../PROJECT_HANDOFF.md)、[项目上下文](../PROJECT_CONTEXT.md) 和 [TODO](../TODO.md)。
2. 执行 `git status --short --branch`，先保护未提交改动；不要把 2026-09-04 的工作直接覆盖。
3. 核对环境和服务状态，再按 [阶段路线图](roadmap.md) 中最近的验收缺口继续。
4. 完成开发后更新项目上下文、TODO 和 CHANGELOG；仅将已验证的任务标为完成。
5. 文档不得粘贴 `.env`、JWT Secret、API Key 或真实用户数据。
