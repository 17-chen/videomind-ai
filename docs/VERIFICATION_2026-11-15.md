# 2026-11-15 媒体失败提示与错误回传

## 起点与变更

按 AGENTS 和当前交接恢复，main `4da1249` fetch 后与 origin/main 一致。保留原未跟踪 outputs/ 和 backend/:memory:.ses，不读取、提交或清理其内容。

源码核查发现：yt-dlp 的异常 str 会进入 VideoProcessingError，经流水线写入 Video.processing_error，再进入 VideoTask.error 和本人 API；云 Whisper 也会附加 SDK 原始错误。错误正文可能携带签名链接、代理凭据、服务商响应或本机路径，因此仅有日志不打印堆栈还不够。

- 下载未知异常只保存“视频下载失败”；Cookie 文件缺失只给固定配置提示。原有 Bilibili 412 指引、容量413、低空间507和下载超时规则保留，不附加外部正文。
- 云转写在 SDK 初始化/请求边界统一处理错误。AuthenticationError、RateLimitError、APITimeoutError、APIConnectionError 分别给固定认证、限流/额度、超时、连接文案；其他错误使用固定转写失败提示。分类仅依据类型，不解析不可信响应正文。
- 音频提取、云/本地转写的缺失输入错误不再附带绝对路径。已有本地 Whisper 失败的类型提示不变。
- 不增加应用重试、密钥回退或模型调用；SDK 自身原有重试行为不变。历史数据库错误不回写清洗；用户本人的正常资料 URL、媒体引用与正文保持原有访问规则。

这些测试使用模拟身份、下载器/ASR 响应；本地 HTTP 用例使用真实 yt-dlp。没有调用真实 OpenAI/DeepSeek，没有重处理已完成视频。前端源码未改，不覆盖运行中的开发构建目录；GitHub CI继续覆盖前端构建、类型、lint和回归。
