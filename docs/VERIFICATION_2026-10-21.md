- 2026-10-21 后续演练：在实际 PostgreSQL 上创建独立临时用户和 `process` 任务，停用空闲常驻 Worker 后，以独立 Python 进程运行真实领取、阶段执行和心跳代码；处理阶段由受控阻塞替代，未调用外部视频、ASR 或模型。运行 96 秒（超过 90 秒租约）后租约仍剩约 84 秒、尝试次数仍为 1，恢复扫描没有错误领取。随后向执行进程发送 SIGKILL（退出码 -9），仅将该测试任务租约提前至过期，恢复后由第二领取者完成（尝试次数 2）。测试用户、视频和任务已删除，常驻 Worker 已重新启动；这证明本机进程中断与心跳路径，不证明真实媒体处理、付费阶段或长期多实例稳定性。
- 修复失联旧 Worker 在任务被重新领取后继续切换阶段、写入成功或覆盖新 Worker 失败状态的风险；阶段更新和完成前增加所有权/租约检查，异常处理也核对所有权。两种旧 Worker 接管竞态测试通过。已进入外部调用的阶段仍无法被同步撤销，其副作用需要真实服务和多实例验收。

- 合成转写与摘要直接写入本地数据库，仅用于验证队列、Worker 与 Chroma 连接；不能当作真实 ASR、模型生成、公开视频或 Supabase 双用户验收。

- 本地嵌入式 Chroma 不适合作为多实例生产服务的证明；正式部署需完成 R6 存储适配和 R5 多实例长期运行演练。
