# 2026-10-24 核查记录：用户请求频率限制

## 实现范围

- 问答请求按用户每分钟最多 20 次，视频 `process`、`run`、`analyze`、`embed` 入队合计每分钟最多 10 次；可用 `MAX_CHAT_REQUESTS_PER_MINUTE` 与 `MAX_VIDEO_TASK_REQUESTS_PER_MINUTE` 配置为 1–1000。超限返回 HTTP 429，响应说明当前上限。原有活动任务上限仍为每用户同时排队加运行最多 2 个。
- 计数保存在 PostgreSQL `request_windows`，按用户和操作类型隔离。窗口从该操作的首次请求开始，满 60 秒后重置；问答在检索/模型调用前消耗名额，即使资料为空也计数。四个视频任务接口在查询视频与入队前消耗名额，重复请求、超活动任务上限和配置错误也计数；实际活动任务名额只在入队成功后占用。
- 请求计数先锁定用户行并单独提交，跨 API 会话串行判断名额，之后不持有数据库锁等待模型或任务处理。demo 模式共享一个演示用户，因此也共享该用户的名额。

## 边界

这是应用层按用户的短窗口限制，尚未覆盖匿名流量、用户存储总量、上传带宽、Worker 实际并行数或外部模型服务的账单额度。真实 Supabase 双用户、付费服务和长期多实例负载尚未验收。迁移前的备份只用于本机恢复，不提交 Git。
