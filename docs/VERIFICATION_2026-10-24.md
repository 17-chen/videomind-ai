# 2026-10-24 核查记录：用户请求频率及上传容量限制

## 实现范围

- 问答请求按用户每分钟最多 20 次，视频 `process`、`run`、`analyze`、`embed` 入队合计每分钟最多 10 次；可用 `MAX_CHAT_REQUESTS_PER_MINUTE` 与 `MAX_VIDEO_TASK_REQUESTS_PER_MINUTE` 配置为 1–1000。超限返回 HTTP 429，响应说明当前上限。原有活动任务上限仍为每用户同时排队加运行最多 2 个。
- 计数保存在 PostgreSQL `request_windows`，按用户和操作类型隔离。窗口从该操作的首次请求开始，满 60 秒后重置；问答在检索/模型调用前消耗名额，即使资料为空也计数。四个视频任务接口在查询视频与入队前消耗名额，重复请求、超活动任务上限和配置错误也计数；实际活动任务名额只在入队成功后占用。
- 请求计数先锁定用户行并单独提交，跨 API 会话串行判断名额，之后不持有数据库锁等待模型或任务处理。demo 模式共享一个演示用户，因此也共享该用户的名额。

## 上传来源视频累计容量

- `MAX_USER_UPLOAD_MB` 默认 5120 MB，上传策略接口返回 `max_user_upload_bytes`。文件通过媒体校验和重复校验后，锁定用户行并统计其已保存上传视频的实际文件大小；新文件将超限时返回 413，不发布临时文件。删除文件后释放额度。
- 定向 API 测试覆盖超限、临时文件清理、跨用户独立额度及删除后重新上传；完整后端回归 89 passed，Ruff 通过。一次性 PostgreSQL 16 中用两个会话同时上传各 700 KB、额度 1 MB，结果为 201/413、数据库仅一条记录、磁盘仅一个完整文件且无 `.part`；临时容器已移除。
- 上传配额首轮 [CI 运行 40055464113](https://github.com/17-chen/videomind-ai/actions/runs/40055464113) 的后端 88/89 通过；删除后释放额度测试触发默认 Chroma 路径在 CI 不可写而返回 503。已在该用例隔离向量删除调用，本地完整回归仍为 89 passed；修复提交的 CI 结果需单独核对。
- 当前为上传来源视频容量限制，按本地文件大小统计。下载视频、提取音频、转写与笔记、向量索引没有统一的用户存储账本；多实例部署需共享文件存储才能依据相同文件尺寸判定，云存储适配后仍需重新验收。

## 边界

这是应用层按用户的短窗口限制和上传视频容量限制，尚未覆盖匿名流量、所有文件类型的用户存储总量、上传带宽、Worker 实际并行数或外部模型服务的账单额度。真实 Supabase 双用户、付费服务和长期多实例负载尚未验收。迁移前的备份只用于本机恢复，不提交 Git。
