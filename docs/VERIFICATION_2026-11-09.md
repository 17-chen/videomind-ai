# 2026-11-09 问答来源复核与编号引用

## 目标和改动

推进 R2/R7 中无需真实账号操作的问答保护。起点 `82b10a5` 与 origin/main 一致，上一轮 [CI 42541025399](https://github.com/17-chen/videomind-ai/actions/runs/42541025399) 前后端通过。

此前问答直接使用向量结果，业务 Session 未参与来源验证。现在仍向检索后端传入本人 user_id，但在来源序列化、构造上下文和调用模型之前，用一次限定候选 ID 与本人 user_id 的 SQL 查询复核 Video 是否存在且属于本人。过滤无权访问、已删除、空文本和重复的视频，保留有效结果的检索顺序。不修复或删除向量、不扩展检索范围、不自动重建索引。过滤后不足 limit 时返回较少来源，不追加外部调用；全部无效时返回原有中英文无相关资料提示且不调用模型。SQL 校验失败向上报错，不回退为信任索引。

生成上下文使用连续 [1]、[2] 编号，来源卡片按相同顺序显示编号并链接本人详情。提示词要求结论引用相应编号、资料不足时说明、不编造来源/时间戳，并将资料中的指令作为正文处理。无 schema、API 响应结构、依赖或模型参数变更。

## 边界和后续

这些是索引结果进入问答前的额外保护，不能替代真实 Supabase 双账号验收；不证明损坏索引中“合法本人 ID 与错误正文”的完整性。正文和来源元信息仍来自检索快照，编辑后索引同步失败时可能保留旧内容；验证后发生的删除不能撤回已经开始的模型调用。没有用长事务锁住视频来阻塞删除。
