# 剩余开发范围与估算

核对日期：2026-10-21。依据当前代码、TODO 和 roadmap 估算；不按页面数量计算完成百分比。这里的“全部”按现有路线图理解为补齐本地功能并形成可供小规模多用户使用的版本，包含基础队列、配额、监控和持久化；不继续增加新的产品需求。

## 现在的状态

URL 视频登记、上传入口、资料编辑、处理流程、AI 笔记、个人模型密钥、问答、删除、知识库分页和搜索已有实现。2026-10-20 后端 69 项测试通过，前端构建和静态检查通过。上传已做自生成视频的本地 HTTP 烟测与模拟全链路，真实 ASR/模型调用未验收。Supabase 认证有代码和模拟用户测试，真实项目还没有验收。可选本地 ASR/BGE 有接入代码，真实音频、下载和效果仍待验证。

当前仍主要是本地演示：处理使用 PostgreSQL 持久任务与独立 Worker，文件留在本地，向量默认使用 hash + Chroma。不能把真实账号尚未配置当作所有剩余工作的唯一障碍。

## 需要项目所有者参与的事项

- 创建并授权使用 Supabase 及部署平台账号，选择项目和费用方案；将必要配置放入本地环境或平台密钥设置。
- 准备可用的个人模型账户与测试额度，确认真实服务商计费；完成需要本人操作的账号验证。
- 若必须验收私人或受限视频，需要提供有权使用的素材或授权凭证；公开测试素材和本地模型下载可由开发侧继续处理。

不在文档或 Git 中保存任何真实密钥。上述账号注册、授权和等待时间不计入 50–80 小时；账号配置后的测试和修复已经计入。

## 推荐开发顺序

1. 真实本地模型和视频烟测，使用本轮固定评测找出质量问题。
2. 上传和资料编辑，收束本地完整操作。
3. 持久化队列、取消和状态恢复。
4. 存储适配、部署配置与账号就绪后的端到端验收。
5. 密钥轮换、配额、监控、恢复和上线检查收尾。

## 详细任务与验收标准

以下编号用于跨聊天追踪；2026-10-16 交接时均未完成。表中的五个工作包仍是工时汇总口径，下面的任务不额外叠加工时。

### R1 — 真实本地模型与检索对照（优先级 P0）

- [ ] 确认可选依赖能在目标机器或容器安装，记录模型缓存目录和实际使用的模型版本。
- [ ] 用允许使用的短音频运行 faster-whisper，检查实际转写内容、耗时、内存和无字幕错误路径。
- [ ] 使用 `scripts.evaluate_retrieval --provider bge_zh` 跑相同语料，保存模型、数据指纹、top-k 和逐题报告。
- [ ] 增加允许使用的真实转写与人工答案标签，覆盖同义改写、长文末尾、多视频答案和跨用户相近资料。
- [ ] 比较分段参数与候选去重；保留原始基线和失败题，不通过改答案标签掩盖回归。

验收：有可复现的安装/运行步骤、真实音频结果、模型对照报告及剩余失败项；用户隔离违规为 0。质量阈值须在真实样例上制定，不能直接沿用小型虚构语料的 96.43%。若下载受限，保留准确原因并继续不依赖该下载的任务。

### R2 — 真实视频到问答的完整流程（优先级 P0）

- [ ] 选择一个公开且有权测试的短视频，跑通创建、下载/字幕、分析、入库和问答。
- [ ] 核对分析与回答确实使用当前用户自己的配置；缺 Key、错误 Key、额度不足时给出明确提示。
- [ ] 检查笔记内容、来源链接和回答引用是否与原始资料一致，并保存脱敏记录。
- [ ] 模拟向量失败后续跑，确认复用已保存的转写和摘要，避免再次调用已完成的生成步骤。

验收：每阶段有实际结果和用户可见失败反馈，能从知识库追溯来源。真实服务商调用需要可用账户和额度；在此之前可完成模拟与失败场景测试，但不能标记真实验收通过。

### R3 — 本地视频上传（优先级 P1）

- [x] 新增本人视频上传入口和服务端接口，使用服务端生成的文件名；2026-10-19 本地 HTTP 烟测通过。
- [x] 校验扩展名、MIME、大小及实际视频流，重复内容返回 409，前端显示上传和处理状态；测试覆盖超限与无效内容。
- [x] 将上传视频接入现有转写/分析/向量流程，区分文件来源与 URL 来源；模拟全链路测试通过，真实模型调用待验收。
- [x] 实现用户归属校验及删除时的文件清理，测试覆盖越权、超限和不支持格式；本地 HTTP 删除与文件清理通过。

验收：代码和本地上传/删除烟测已完成。仍需在可用 ASR 与本人模型配置下实测从上传到笔记/入库，以及真实 Supabase 双用户隔离；模拟全链路不能替代这些真实验收。不要仅依据文件扩展名判断媒体有效。

### R4 — 元信息、分类与笔记编辑（优先级 P1）

- [x] 本人可修改标题、备注、标签和分类，前后端长度约束一致（2026-10-20，权限/校验测试与本地 API 烟测）。
- [x] 可修改 Markdown 笔记；手工笔记在再次 AI 分析时保留，AI 摘要仍更新（2026-10-20，模拟分析测试）。
- [x] 修改影响检索的内容后立即更新索引；失败时记录状态并提供重试入口（2026-10-20，模拟向量故障测试）。
- [x] 覆盖处理中修改冲突、其他用户拒绝访问和旧索引仍可搜索的边界（2026-10-20，数据库/API 测试；真实多用户服务待验收）。

验收：列表、详情、笔记与检索内容一致，向量失败不会静默伪装为全部更新成功。覆盖手工笔记的规则在实现前说明。

R4 代码和本地接口检查已完成。跨 PostgreSQL 与 Chroma 的更新不是单个原子事务；失败时数据库展示新内容、旧向量仍可检索，详情页提示并可重试。真实 Supabase 双用户、真实模型问答与多实例并发仍在后续验收范围。

### R5 — 持久化任务、重试与取消（优先级 P1，上线前必须）

- [x] 当前本地版采用 PostgreSQL 任务表与独立 Worker，暂不增加 Redis；部署负载明确后再评估 Celery（2026-10-21）。
- [x] 持久化任务归属、当前阶段、尝试次数、错误和时间，支持独立 Worker（2026-10-21，本机 PostgreSQL + Worker 验证）。
- [x] 同视频重复请求拒绝，`SKIP LOCKED` 防并行领取；分析与可能已计费的云端转写失联后停止自动重试（2026-10-21，API 测试与真实 PostgreSQL 并发检查）。
- [x] 排队任务可直接取消，运行中在阶段边界停止后续处理（2026-10-21，Worker 检查点测试）。
- [ ] 完整故障演练：已验证 API 重启后队列保留、真实 Worker 执行、PostgreSQL 双领取竞争与模拟租约过期；仍需真实 Worker 强制中断、长任务心跳、付费步骤和多实例长期运行验证。

验收：进程重启不丢已接受任务，重复投递不产生重复结果；用户只能查看或取消自己的任务。2026-10-21 已有本机队列与独立 Worker 实测，但真实 Worker 强制中断与长任务心跳尚未完成，因此 R5 不标记整项验收完成。
