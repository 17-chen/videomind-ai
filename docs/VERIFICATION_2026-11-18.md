继续 R5/R8 已知缺口：原下载预算只在 yt-dlp 回调检查，阻塞 HTTP 或 ffmpeg 合并等待期间缺少独立监督。现在生产流水线通过 managed_downloader 启动独立 Python 下载进程组，父进程约每0.25秒检查当前阶段总量、余量和整体超时；普通返回/异常均先停止组、回收组长，再交还外层发布或清理。

下载器用线程观察父PID；Worker消失时停止自身组。结果帧完成后组长保持存活等父进程确认并停止组，封闭“结果已发出但父进程此时退出”的间隙。父端waitid/WNOWAIT延后回收，停止组后才wait，避免PID复用问题。缺必需接口时明确失败，不回退无限制下载；已验Docker/Linux，Python3.12原生macOS缺waitid。设计及官方语义链接见 [决策](../DECISION_LOG.md) 与 [边界](TEMPORARY_STORAGE.md)。

Worker到下载器的控制参数经私有匿名临时文件/FD传递，不出现在监督入口argv或日志，标准输出/错误使用DEVNULL；yt-dlp自身外部下载器的参数行为不在这项保证中。请求最多256KiB、元信息结果最多1MiB，超大元信息失败；结果必须属于本次视频、URL和暂存目录。子进程接收实际暂存路径与选定下载配置，保留相对路径发布语义。不改变队列、本人模型配置或收费阶段的恢复规则。
