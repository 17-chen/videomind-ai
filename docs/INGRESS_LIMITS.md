# 认证前流量控制

2026-10-28：本地单进程防护。与 PostgreSQL 中按用户记录的问答/入队配额同时生效。

## 行为与配置

- `MAX_INGRESS_REQUESTS_PER_PEER_PER_MINUTE`：每个连接来源每 60 秒最多 300 次。
- `MAX_INGRESS_REQUESTS_PER_MINUTE`：每个 API 进程每 60 秒合计最多 3000 次；来源额度耗尽的请求也消耗合计额度。
- 使用单调时钟、线程锁和最多 4096 个来源的内存表。来源表满时拒绝新来源，直到旧窗口到期，不驱逐未到期计数；拒绝不延长窗口。
- 不依据 `Authorization` 判断是否计数。匿名、错误令牌、已认证请求、404、readiness 和上传均在读取请求正文、认证调用与数据库访问前检查。
- 超限响应为 429，包含 `detail`、整数秒 `Retry-After`、`Cache-Control: no-store`、请求编号及允许来源的 CORS 响应。前端支持对应中英文提示。
- 只有 `GET /health` 的廉价存活检查豁免；CORS 中间件直接处理的合法预检不会调用业务处理，也不消耗此额度。网关仍需约束预检和存活探针流量。

## 代理和部署边界

Compose 与 Dockerfile 的 Uvicorn 启动命令显式使用 `--no-proxy-headers`。限流按 ASGI 连接来源计算，应用不解析 `X-Forwarded-For` 或 `Forwarded`，避免任意伪造转发头切换身份。自定义启动命令也必须保留此参数。

位于 Next.js、NAT 或反向代理后的请求可能共享一个来源额度。默认值是本地起点，需要按实际使用调整；不能直接把它当作生产每用户额度。关闭代理头也意味着应用看到连接本身的协议/地址；目标平台须验证 HTTPS 重定向、尾斜杠跳转和代理行为。

计数随进程重启清空，多 Worker/多实例分别计数，固定窗口边界可能出现相邻窗口的突发流量。此实现不限制连接数、并发在途请求、网络带宽或单次请求大小，不替代上传校验及用户任务配额。生产应在受控网关设置统一流量、正文大小、连接/超时限制，并限制 API 直连；真实目标平台与多实例负载尚未验收。

不要为了按客户端 IP 分流直接信任所有转发头。后续接入可信代理时必须明确代理名单、网络访问边界及统一计数方案，再做部署验证。
