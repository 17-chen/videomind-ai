# 🧰 VideoMind AI 技术栈教学


## 不要把技术栈当成购物清单

一个项目使用很多技术，不是因为“越多越高级”，而是因为不同问题需要不同工具。

VideoMind AI 的技术栈可以分成六组：

| 系统工作 | 主要技术 | 一句话职责 |
|---|---|---|
| 用户界面 | Next.js、React、TypeScript、Tailwind CSS | 让用户操作和查看视频知识 |
| 后端 API | FastAPI、Pydantic | 接收请求、校验数据、组织业务流程 |
| 业务数据 | PostgreSQL、SQLAlchemy | 保存用户、视频、字幕和摘要 |
| 视频处理 | yt-dlp、ffmpeg、ASR | 把视频变成可以分析的文字 |
| AI 理解 | LangGraph、DeepSeek、OpenAI-compatible SDK | 把 transcript 整理成结构化知识 |
| 语义检索 | Embedding、ChromaDB、RAG | 从视频知识库中找资料并回答 |

下面逐组讲清楚它们是什么、为什么需要，以及在项目中如何连接。

## 🖥️ Next.js + React：搭建用户可以操作的产品

### 先用生活类比理解

React 像一套可以重复组合的积木：按钮、卡片、表单和导航都可以做成组件。Next.js 像整套建筑规则，规定页面放在哪里、URL 怎样对应页面、哪些内容在服务器生成。TypeScript 则像积木接口的尺寸标准，尽量在运行前发现“这个零件接不上”。

### 在项目中怎么工作？

`frontend/app/` 使用 Next.js App Router：文件夹和 `page.tsx` 共同决定 URL。Dashboard 和 Library 页面可以在服务器端请求后端数据；需要处理输入、点击和加载状态的组件使用 `"use client"` 在浏览器运行。

例如 `VideoSubmitForm` 保存用户正在输入的 URL、标题和标签。提交后它调用统一 API 客户端，成功时跳转到视频详情页。`VideoActions` 则提供“处理视频、AI 分析、写入知识库”三个动作。

### 为什么不只用普通 HTML？

普通 HTML 足以展示静态文字，但这个项目需要表单状态、异步请求、页面导航、错误提示和动态知识卡。React 的组件模型让这些交互可以复用；Next.js 又补上路由、服务端渲染和构建能力。

### 代价是什么？

项目同时存在浏览器、Next.js 服务器和 FastAPI 后端三个网络视角，所以 API 地址不能只写一个。`NEXT_PUBLIC_API_BASE_URL` 给浏览器使用，`INTERNAL_API_BASE_URL` 给 Docker 网络中的 Next.js server 使用。

## 🚪 FastAPI + Pydantic：建立清晰的后端入口

### 先用生活类比理解

FastAPI 像办事大厅：每个窗口处理一种业务。Pydantic 像材料审核员，先检查用户提交的数据是否符合格式。Service（服务层）则是后台真正办理业务的部门。

### 一次请求经历什么？

以“提交视频”为例：

1. FastAPI 根据 `POST /api/v1/videos` 找到路由。
2. Pydantic 把 JSON 验证成 `VideoCreate`。
3. FastAPI dependency 提供数据库 Session 和 demo user。
4. 路由调用 `create_video` service。
5. SQLAlchemy 写入数据库。
6. Pydantic 把返回对象转换成稳定的 `VideoRead` JSON。

### 为什么要分路由和服务层？

路由关心 HTTP，服务层关心业务。如果未来增加 CLI、定时任务或消息队列，它们可以直接复用 service，不必伪造 HTTP 请求。单元测试也更容易针对业务函数编写。

### 代价和限制

当前后端使用同步数据库 Session，理解简单，但长时间的视频下载不能占住普通请求。项目先使用 `BackgroundTasks` 让响应提前返回；生产环境仍需要更可靠的任务系统。

## 📚 PostgreSQL + SQLAlchemy：保存可以信任的业务数据

### 它们分别是什么？

PostgreSQL 是关系数据库，负责真正存储数据。SQLAlchemy 是 Python ORM，让开发者使用 Python 类和查询表达式操作数据库。

把数据库想成一间档案室：Video 是视频档案，Transcript 是逐字稿，Summary 是 AI 整理结果，User 表示档案属于谁。外键和 relationship 记录档案之间的关系。

### 为什么不能只保存 Markdown 文件？

Markdown 适合阅读，却不擅长回答“这个用户最近的 20 个视频是什么”“筛选 Technology 分类”“这个 transcript 属于哪个 Video”等结构化问题。关系数据库为查询、约束和事务而设计。

### 当前需要升级的地方

应用启动时使用 `create_all` 建表，并用若干 `ALTER TABLE IF NOT EXISTS` 兼容开发期字段。这能快速保持 MVP 可运行，但无法像正式 migration 那样记录每一次 schema 变化、升级顺序和回滚方式。项目已安装 Alembic，下一步应真正建立 migration。

## 🎬 yt-dlp + ffmpeg + ASR：把视频翻译成 AI 能读的文字

大语言模型最容易处理文本，而用户交给系统的是视频。因此项目需要一个媒体转换层。

- **yt-dlp** 下载视频、元数据和平台提供的字幕。
- **字幕解析器** 去掉时间戳、HTML 标签和重复字幕行。
- **ffmpeg** 在没有字幕时从视频中抽取音频。
- **ASR** 将音频转写成 transcript。

处理顺序不是随意的。字幕优先可以避免昂贵的语音识别；只有找不到字幕时才提取音频。当前 ASR 默认关闭，所以系统实际上更适合“有可下载字幕的视频”。

视频平台可能限制云服务器访问，也可能需要 Cookie、代理或特定系统依赖。因此“本地能下载”不能自动推导为“任意云环境都能下载”。

## 🧠 LangGraph + DeepSeek：把 transcript 变成知识

### LangGraph 做什么？

LangGraph 不等于模型。它负责组织模型任务的步骤和状态。本项目先运行 analysis 节点，再运行 markdown 节点。流程目前很简单，但以后可以增加重试、人工审核、分支或 embedding 节点。

### DeepSeek 做什么？

DeepSeek 阅读 transcript，生成标题、摘要、核心观点、关键词、分类、时间线和行动建议。项目使用 OpenAI Python SDK 连接 DeepSeek-compatible API；SDK 是客户端，真正的模型提供商由 base URL 和配置决定。

### 为什么要求 JSON？

模型的自然语言输出不稳定，但数据库需要稳定字段。项目要求模型返回 JSON，再用 Pydantic 验证。只有验证通过的数据才用于生成 Markdown 和写入 Summary。

### LangGraph 是否有点“用重了”？

目前两个线性节点用普通函数也能实现。采用 LangGraph 的价值主要是为未来复杂流程预留结构；代价是增加一个需要学习和维护的抽象。是否值得，要看后续是否真的增加分支、重试和多节点协作。

## 🔎 Embedding + ChromaDB + RAG：从“保存”升级为“能找到”

### 三个概念不要混在一起

- **Embedding（向量表示）**：把文本变成一组数字。
- **ChromaDB（向量数据库）**：保存这些数字并寻找最相近的内容。
- **RAG（检索增强生成）**：先检索资料，再让 LLM 基于资料回答。

### 在项目中如何连接？

索引视频时，项目把标题、标签、摘要、笔记和 transcript 合并为一个文档。本地 embedding service 把文档转换成 384 维向量，ChromaDB 保存向量、原文和 user ID。

用户提问时，问题用相同算法变成向量。ChromaDB 找出最近的若干文档，后端把它们整理成上下文交给 DeepSeek。回答返回时还附带来源视频。

### 当前 hash embedding 的真实水平

它通过哈希把词和中文字符分配到向量位置，具有本地、免费、确定性的优点。但它没有经过语义训练，不真正理解“创业”和“商业化”的概念关系。因此它适合验证系统接口和数据流，不代表最终检索质量。

升级前不应只说“换一个更强模型”。更好的做法是先准备一组中文问题和正确视频，建立召回率评测，再比较 bge-m3、sentence-transformers 或托管模型。

## 🐳 Docker Compose：让整套系统容易在本地启动

Docker Compose 同时定义 PostgreSQL、ChromaDB、Adminer、后端和前端。它统一端口、服务依赖和持久卷，减少“我的电脑能跑、你的电脑不能跑”的环境差异。

但容器化不等于生产就绪。当前前端运行 `next dev`，后端运行 `uvicorn --reload`，并把源码目录挂载进容器。这些是开发体验设计。生产还要解决启动模式、HTTPS、域名、任务队列、migration、认证、监控和备份。

## 🧩 技术是怎样协作的？

```text
React 组件收集用户操作
→ Next.js 页面和 API client 组织请求
→ FastAPI + Pydantic 接收并验证
→ Service 执行业务
→ SQLAlchemy + PostgreSQL 保存状态
→ yt-dlp / ffmpeg / ASR 产生 transcript
→ LangGraph + DeepSeek 产生知识
→ Embedding + ChromaDB 建立检索
→ RAG + DeepSeek 回答问题
```

## 本章小结

技术栈的核心逻辑是：每项技术只解决自己擅长的问题。理解它们之间传递的输入和输出，比记住版本号更重要。
